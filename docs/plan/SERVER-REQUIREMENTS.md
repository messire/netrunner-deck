# Свой сервер вместо Herdr — функциональные требования (MVP)

Статус: черновик, согласуется. Записано 2026-11-20 по итогам обсуждения. Реализация не начата.
Связано: `docs/plan/ROADMAP-own-runtime.md`.

## Принятые решения

- Стек — Rust, без Zig и без .NET.
- Протокол совместим с Herdr: те же методы, параметры, события и поля, которыми пользуется Deck.
  Один адаптер в Deck работает и с Herdr, и со своим сервером. Новое добавляется только расширениями.
- В MVP две платформы: Windows-сервер на локальной машине и Linux-сервер на удалённой (VDI).
- Федерация входит в MVP: Deck работает с несколькими серверами одновременно (бывший S6).
- К одному серверу могут подключаться несколько клиентов сразу.
- Сплитов нет: в табе одна сессия.
- Фокуса на сервере нет. Какую сессию показывать, решает клиент.
- Размер терминала фиксирован на сервере (по умолчанию 120×40, задаётся в конфиге). Метода resize нет.
- Статус агента — только Claude Code и только по его хукам. Экранного детектора и других агентов нет.
- После перезапуска сервера сессии восстанавливаются, агенты поднимаются через `claude --resume <id>`.
- Путь всегда один: Deck работает с данными только через сервер, и с локальным тоже. Прямого
  чтения диска и вызовов git из Deck нет.
- Аккаунты Claude — свой cswap на Rust внутри сервера (см. §11), внешний `cswap` не нужен.

## 1. Процесс и транспорт

- Демон, живёт дольше Deck, одна инстанция на пользователя. Без TUI.
- Локально: named pipe на Windows, unix-сокет на Linux.
- Удалённо: Deck ходит к unix-сокету VDI через SSH-туннель. Авторизацию даёт SSH.
- Формат: одна JSON-строка `{id, method, params}`, ответ `{id, result|error}`. Подписка — долгое соединение.
- `ping` отдаёт версию протокола.
- Схемы методов и событий в JSON Schema (`schemars`), CLI генерируется из них.

## 2. Модель сессий

- Иерархия workspace › tab › pane, стабильные id, номер, label. Порядок задаёт сервер.
- Workspace может быть привязан к git worktree: `repo_key`, `repo_name`, `branch`,
  `is_linked_worktree`, `checkout_path`.
- `workspace.list/get/create(cwd, label, env, source_workspace_id)/rename/close(close_group)`
- `tab.list/create(workspace_id, cwd, label)/rename/close`
- `pane.list/get/rename/close`
- Дерево (workspaces, tabs, panes с cwd и `agent_session`) сохраняется на диск для восстановления.

## 3. Терминал на сервере

- Каждая сессия — процесс Claude Code в псевдотерминале (ConPTY на Windows, PTY на Linux)
  с cwd и env. Клиенту терминал не виден, он работает только через JSON.
- `pane.send_text`, `pane.send_keys` (именованные клавиши).
- `pane.read(source recent|screen, lines, format ansi|text)` → текст, курсор, `revision`.
  Состояние экрана — `alacritty_terminal`.
- Завершение процесса → событие `pane.exited`.

## 4. Статус агента

- Поля pane: `agent`, `display_agent`, `agent_status` (idle|working|blocked|done|unknown),
  `tokens`, `agent_session` (uuid сессии Claude Code).
- Агрегаты статуса на tab и workspace, `agent.list`.
- Источник — хуки Claude Code (`Stop`, `Notification`, `PermissionRequest`, ...); сервер сам
  ставит хуки на своей машине.

## 5. Worktree

- `worktree.list(cwd)`, `worktree.open(path)`, `worktree.create`.

## 6. События

- `events.subscribe` по списку типов: `workspace.created/updated/renamed/closed`,
  `tab.created/closed/renamed/moved`, `pane.created/closed/updated/exited`,
  `pane.agent_status_changed`, `pane.output_changed` (с `revision`, частые изменения склеиваются).
- Неизвестный тип → ошибка.

## 7. Расширения сверх Herdr

- `session.start {cwd, agent, args, prompt}` — запуск агента сразу с промптом.
- Транскрипты: Deck сейчас читает JSONL Claude Code из локального `~/.claude`. Для удалённого
  сервера файлы лежат на нём, поэтому сервер отдаёт их по протоколу: чтение транскрипта сессии
  с позиции и событие о дописанных строках.
- Информация об узле (имя машины, ОС, версия) для федерации.

## 8. Федерация (в Deck)

- Список серверов в настройках Deck; Deck подключается к каждому сам, у каждого своё
  подключение и свой reconnect.
- Измерение `machine` в дереве и в ключах сессий.
- Дизайн не должен закрывать вариант, когда серверы связаны между собой и Deck ходит в один:
  id узла входит в ключи, протокол не предполагает «клиент всегда напрямую у сервера».

## 9. Функции Deck, которые сейчас работают с локальным диском

Всё ниже идёт через протокол на любом узле, включая локальный: путь один. Код, который сейчас
лежит в `archive.rs`, `harness.rs`, `uplink.rs`, `transcript.rs`, переезжает на сервер.

| Функция | Что делает локально сейчас | Что нужно от сервера |
|---|---|---|
| Архив | Сканирует `session.json` и снапшоты Herdr, `~/.claude/projects/*/*.jsonl`, `~/.claude/history.jsonl`; восстанавливает сессии; удаляет транскрипты и делает `git worktree remove`; описания пишет теневым `claude -p` | Список закрытых сессий узла (id, cwd, промпты, worktree, есть ли транскрипт); восстановление (через `--resume`); удаление транскриптов и worktree; запуск описания на узле. Своё `archive.json` (описания, тумбстоуны) — у Deck, с ключом узла |
| Чат (транскрипт) | Читает хвост JSONL и следит за ростом файла | Чтение транскрипта с позиции и событие о новых строках (уже в §7) |
| Harness | Читает `~/.claude` и `.claude` репозиториев: CLAUDE.md, settings, skills, agents, commands, rules, MCP; пишет теги в файлы | Список элементов конфигурации для личного каталога и репозиториев узла, чтение файла, запись (теги) |
| Uplink | `git` по чекаутам: отставание от upstream, грязность, `git pull`, лог PR | Статус чекаута, `pull` и его лог на узле. Журнал `uplink.json` — у Deck, с ключом узла |
| Quickhacks | Закреплённый список хранит Deck; запуск — оркестрация `worktree.*`, `tab.create`, `pane.send_text` | Только `session.start` на нужном узле; сам список остаётся в Deck |
| Аккаунты (cswap) | Вызывает внешний `cswap` (Python) на этой машине | Свой модуль аккаунтов на сервере узла, см. §11 |

## 10. Где хранится (позже)

Цель на будущее, в MVP не обязательна. Элементы — сессии архива, транскрипты, элементы Harness
(skills, agents, commands), закреплённые Quickhacks — могут жить на сервере или локально:

- перенести локальное на сервер и серверное локально (транскрипт + запись архива, файлы конфигурации);
- удалить на любой стороне;
- в UI видно, где лежит элемент.

Для MVP достаточно, чтобы у каждого элемента был ключ узла, тогда перенос добавится без смены модели.

## 11. Аккаунты Claude (свой cswap)

Порт функций [claude-swap](https://github.com/realiti4/claude-swap) (MIT: сохранить копирайт и
лицензию в NOTICE) на Rust, модулем сервера. Работает на каждом узле со своими аккаунтами.

MVP:
- Список аккаунтов: номер, email, алиас, тариф, активный, использование 5 ч / 7 дней / по моделям
  с временем сброса, статус токена. Это то, что Deck сейчас показывает в пикере F1.
- Добавить текущий вход как аккаунт (в слот, с алиасом), удалить, задать алиас.
- Переключить: по номеру, email, алиасу, на следующий, по стратегии `best` / `next-available`.
- Хранение учётных данных и обновление токенов так, чтобы переключение не ломало идущие сессии.
- Новая сессия (и `--resume` после перезапуска) стартует под последним активным аккаунтом узла.
  Выбора аккаунта на сессию нет.

Позже:
- Автопереключение по порогам (стратегии `best`, `weekly-first`, `consume-first`,
  `priority-consume-first`; пороги на аккаунт, приоритеты, disable/enable, кулдаун).
- Экспорт и импорт аккаунтов, перенос между узлами.

## Вне MVP

- Другие агенты кроме Claude Code, экранный детектор.
- Сплиты, серверный фокус, resize.
- Привязка каталогов к аккаунтам (`cswap map`) и запуск сессии под выбранным аккаунтом (`cswap run`) — не делаем.
