# Roadmap: свой рантайм вместо Herdr

Статус: план на ближайшее будущее, не начат. Записано 2026-11-18 по итогам обсуждения.
Контекст: Deck сейчас — клиент Herdr (форк `herdr-punk`, Local-пайп). Цель — со временем
убрать зависимость от Herdr, сохранив его API как основу, и развивать её дальше своей.

## Обновление 2026-11-20

Требования к MVP — `docs/plan/SERVER-REQUIREMENTS.md`. Решения, которые меняют план ниже:

- Федерация входит в MVP (S6 больше не последний шаг). Решение 1 «сначала сервер, потом
  мультимашинность» заменено на «сервер и федерация вместе».
- В MVP две платформы: Windows локально и Linux на удалённой машине.
- Протокол совместим с Herdr, новое только расширениями. Стек — Rust, без .NET.
- Статус — только Claude Code по хукам, экранного детектора нет (меняет решение 4 и S3).
- Без сплитов, без серверного фокуса, без resize (размер терминала фиксирован на сервере).
- Перезапуск сервера восстанавливает сессии через `claude --resume`.
- Сервер отдаёт транскрипты JSONL по протоколу (для удалённых машин).

## Решения

1. **Сначала сервер, потом мультимашинность.** Поддержка удалённых машин в Deck поверх
   протокола Herdr (`--machine`, SSH-мост, `surface_interest`/`health_check`) при замене
   сервера пошла бы в мусор. Удалённые машины добавляются уже к своему серверу, измерение
   `machine` появляется в Deck один раз.
2. **API Herdr берём за основу.** Лицензия Apache-2.0 (libghostty-vt и portable-pty — MIT)
   позволяет форк и закрытое развитие; обязанности: сохранить LICENSE/NOTICE, помечать
   изменённые файлы, не использовать имя Herdr как своё. Сохранить: схему методов/событий
   с JSON Schema (`schemars`), событийную подписку, замороженные кодеки/generation для
   совместимости, CLI, генерируемый из тех же схем (`cli_params!`).
3. **Стек сервера — Rust, но без Zig.** tokio · `interprocess` (пайпы/unix-сокеты) ·
   serde + schemars · JSON-RPC-подобный протокол по сокету · `portable-pty` (ConPTY —
   патчи Herdr перенести или заменить прямым вызовом через `windows-sys`) ·
   VT-состояние на `alacritty_terminal` (или `vt100`/`vte`) вместо вендоренного
   libghostty-vt — нужно состояние экрана для `pane.read`, не рендер.
4. **Статус агента — из хуков и транскрипта, не из экрана.** Хуки Claude Code (`Stop`,
   `Notification`, `PermissionRequest`), JSONL-транскрипт; экран — только для TERM-режима
   и меню CLI. Манифестный детектор Herdr — fallback для чужих агентов.
5. **Клиент остаётся Deck (Tauri + Solid).** Память — это WebView2 на Windows, release-сборка
   снимет часть; флаги WebView2 (`--disable-gpu-compositing`, лимит renderer) — опция на
   потом. Смена клиентского стека (egui/slint) не планируется.
6. Чего не делать: Go/Node/Python для сервера (PTY/ConPTY, GC, вес), C++/Qt (скорость и
   безопасность разработки).

## Шаги

- [ ] **S0. Runtime-контракт в Deck.** Собрать в один модуль/трейт то подмножество
      методов и событий, которое Deck реально использует (≈15 методов, 3 типа событий:
      `pane.read/send_text/send_keys/list`, `workspace.*`, `tab.create/rename/close`,
      `worktree.list/open/remove`, `events.subscribe`, `pane_output_changed`,
      `*_status_changed`, дерево). Адаптер `HerdrRuntime` — текущая реализация.
      Дёшево, нужно обоим путям, ничего не ломает.
- [ ] **S1. Server-only срез форка.** В `herdr-punk` отрезать TUI и клиентское (feature или
      отдельный бинарь `*-server`): оставить `server/`, `app/api`, `api/schema`, `detect`,
      `platform`, протокол. Переименовать бинарь/сокет/конфиг; `PROTOCOL_VERSION`/generation —
      точка отсчёта. Цель шага — увидеть реальный объём поддержки (288 k строк → ожидаемо
      в 3–4 раза меньше), ускорить сборку.
- [ ] **S2. Замена тяжёлых частей.** libghostty-vt → `alacritty_terminal`; ConPTY-патчи
      portable-pty → перенос/прямой ConPTY; убрать обязательность иерархии
      workspace/tab/pane там, где Deck в неё упиралась (архив, квикхаки).
- [ ] **S3. Статусы из хуков.** Установщик хуков Claude Code (как Herdr ставит интеграцию),
      событие статуса от хука → сервер → Deck; экранный детектор остаётся запасным.
- [ ] **S4. API своими правилами.** Перенести из форка `pane.output_changed` + `revision`;
      добавить `session.start {cwd, agent, args, prompt}` (вместо «дождись промпта и
      напечатай» в restore/quickhacks); события статуса; `pane.surface` по ADR 0001, если
      TERM-режим окажется узким местом.
- [ ] **S5. Адаптер `DeckRuntime` в Deck**, переключение флагом; период двойной работы с
      Herdr и своим сервером на одном контракте.
- [ ] **S6. Удалённые машины.** Свой транспорт (SSH-форвард сокета или агент на машине),
      измерение `machine` в дереве и ключах pane, независимые reconnect.

## Риски

- ConPTY на Windows — самое дорогое и рискованное; выносить в прод под нагрузку как можно
  раньше (S1–S2), чтобы проблемы вылезли до отрыва от upstream.
- Отрыв от upstream Herdr = потеря их фиксов VT/ConPTY; принимаемая цена.
- Детектор по хукам покрывает Claude Code; другие CLI-агенты — только экранный детектор.
